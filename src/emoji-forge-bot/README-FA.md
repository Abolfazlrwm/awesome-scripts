# Emoji Forge AI — از صفر، بدون استفاده از کد پروژه قبلی

> 📬 **تلگرام:** [@Abolfazl_rwm](https://t.me/Abolfazl_rwm)

ربات تلگرام برای شخصی‌سازی پک‌های Custom Emoji: دریافت ایموجی، شناسایی پک،
دانلود فایل‌ها (در صورت دسترسی رسمی)، پاک‌سازی، اعمال هویت بصری، پیش‌نمایش،
پردازش کامل و خروجی ZIP + راهنمای انتشار رسمی.

> این پروژه کاملاً مستقل است. هیچ فایلی از پروژه‌های قبلی ایموجی کپی نشده است.
> انتشار خودکار در پک شخص دیگر از طریق Bot API ممکن نیست؛ ربات فقط می‌تواند
> یک ست جدید بسازد که خودش مالک آن است (بخش «محدودیت‌های رسمی» را ببینید).

## مرحله صفر — یافته‌های محیط (۱۴:۱۷ تهران، ۲۰۲۶-۱۰-۲۸)

- Python 3.12.3، Node 24، FFmpeg 8.1.2، Pillow 10.2.0، requests 2.31.0 — موجود.
- OpenCV و python-lottie نصب نیستند؛ پس پاک‌سازی رستری با Pillow انجام می‌شود
  (پرکردن ناحیه با میانگین حاشیه بیرونی آن، نه Inpainting هوش مصنوعی) و TGS با
  JSON استاندارد پایتون خوانده می‌شود. هیچ ادعای Inpainting AI نشده است.
- دیسک خانگی ۱۴۴ گیگابایت آزاد؛ RAM کلی ۷٫۷ گیگابایت.
- این VM دائمی نیست (ری‌استارت‌های قبلی پروسس‌ها را کشته‌اند و ‎/tmp پاک
  می‌شود). پس اجرای دائمی ربات در اینجا تضمین نمی‌شود؛ معماری طوری است که با
  همان کد به VPS منتقل می‌شود (فایل systemd در ‎systemd/‎).
- ذخیره‌سازی پایدار فقط زیر ‎~‎ است؛ داده پروژه در ‎data/‎ همین پوشه است، نه ‎/tmp.
- هزینه: همه ابزارهای نسخه اول رایگان و متن‌باز هستند. هیچ API پولی، هیچ
  خرید و هیچ اشتراکی در نسخه اول فعال نیست. تنها هزینه آینده، یک VPS کوچک
  برای اجرای دائمی است (در ‎ARCHITECTURE.md‎).

## محدودیت‌های رسمی تلگرام (بررسی‌شده از مستندات رسمی Bot API 10.3 و صفحه Stickers)

منبع: https://core.telegram.org/bots/api و https://core.telegram.org/stickers (بازبینی ۲۰۲۶-۱۰-۲۸)

- پیام دارای ایموجی سفارشی، فقط ‎custom_emoji_id‎ را در Entity می‌دهد.
  با ‎getCustomEmojiStickers‎ می‌توان ‎file_id‎ و (در صورت وجود) ‎set_name‎ آن را گرفت.
  `set_name` در آبجکت Sticker **اختیاری** است؛ پس شناسایی پک کامل تضمین‌شده نیست.
- با ‎getStickerSet(name)‎ می‌توان فهرست کامل یک ست را گرفت؛ سپس هر فایل با
  ‎getFile‎ دانلود می‌شود. اگر ‎set_name‎ در پاسخ نبود، پک کامل قابل‌استنتاج
  نیست — مسیر جایگزین: لینک ‎t.me/addemoji/<name>‎ یا ارسال مستقیم فایل‌ها.
- ‎createNewStickerSet‎ با ‎sticker_type=custom_emoji‎ در API فعلی وجود دارد،
  ولی ست ساخته‌شده متعلق به کاربرِ مالک است و ربات فقط همان ست را می‌تواند
  ویرایش کند (‎addStickerToSet‎ و غیره). ویرایش پک شخص دیگر ممکن نیست.
  نام ست: ۱ تا ۶۴ کاراکتر، فقط حروف/عدد/خط زیر، بدون خط زیر متوالی، و باید
  به ‎_by_<bot_username>‎ ختم شود. در ساخت اولیه ۱ تا ۵۰ ایموجی؛ سقف ست
  ایموجی ۲۰۰ عدد است (ست معمولی ۱۲۰ عدد).
- محدودیت‌های فایل: ثابت PNG/WEBP؛ برای استیکر یک ضلع دقیقاً ۵۱۲px و تا ۵۱۲KB،
  برای ایموجی دقیقاً ۱۰۰×۱۰۰؛ متحرک TGS ۵۱۲×۵۱۲، تا ۶۴KB، حداکثر ۳ ثانیه و ۶۰ فریم بر ثانیه؛
  ویدیویی WEBM با VP9 تا ۲۵۶KB، حداکثر ۳ ثانیه و ۳۰ فریم بر ثانیه، بدون صدا؛
  برای ایموجی ویدیویی دقیقاً ۱۰۰×۱۰۰.
- نکته Premium: ساخت ست ایموجی برای همه آزاد است، ولی افزودن و استفاده از
  ست‌های سفارشی در چت‌های دیگر، ویژگی کاربران Telegram Premium است (در
  Saved Messages برای همه آزاد است). انتشار ست، استفاده غیر-Premium را تضمین نمی‌کند.
- پک Adaptive: اگر ست با `needs_repainting` ساخته شود، رنگش با رنگ متن/تم
  عوض می‌شود؛ نسخه ۰٫۳ این نوع را پشتیبانی نمی‌کند.
- تفاوت تولید فایل و انتشار پک رعایت شده است: این پروژه فایل می‌سازد؛
  انتشار یا با ساخت ست جدید توسط خود ربات است، یا با راهنمای دستی
  (ادیتور داخل اپ تلگرام / ‎@Stickers‎) با فایل‌های ZIP خروجی.

## نصب و اجرا

```bash
cd emoji-forge-ai
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env   # فقط در .env توکن را بگذارید؛ هرگز در کد یا گیت نه
python3 run.py         # بدون توکن، با پیام راهنما و کد خروج ۲ متوقف می‌شود
```

> نصب در venv مهم است: بسته‌های `arabic-reshaper` و `python-bidi` برای
> رسم درست نام/واترمارک فارسی لازم‌اند و در venv این پروژه نصب و تست شده‌اند.
> بدون آن‌ها، نام فارسی عمداً رسم نمی‌شود تا حروف جدا نشوند.

ربات با Polling کار می‌کند (بدون نیاز به دامنه/وب‌هوک). برای VPS، فایل
‎systemd/emoji-forge-ai.service‎ را ببینید.

## اتصال توکن به‌صورت امن

1. در تلگرام به ‎@BotFather‎ بروید، ‎/newbot‎ بزنید و توکن را بگیرید.
2. توکن را فقط در فایل ‎.env‎ (روی سرور خودتان) بنویسید:
   ‎EMOJI_FORGE_TOKEN=123456:ABC...‎
3. توکن را هرگز در چت، لاگ، کد یا مخزن عمومی نگذارید. لاگ‌های این پروژه
   توکن را سانسور می‌کنند (‎security.redact‎).
4. اگر توکن لو رفت، در ‎@BotFather‎ با ‎/revoke‎ آن را باطل کنید.
5. مدیرها: ‎EMOJI_FORGE_ADMIN_IDS‎ را با شناسه عددی تلگرام مدیرها پر کنید؛
   دستورهای مدیریتی فقط برای آن‌ها باز است.

## دستورهای ربات (فارسی، راست‌چین)

- ‎/start‎ — منو و توضیح محدودیت‌ها و نکته حقوقی مالکیت
- ‎/help‎ — راهنما
- ‎/brand‎ — نمایش پروفایل برند فعلی
- ‎/brand_name <نام>‎ — ثبت نام برند
- ‎/brand_color <#HEX>‎ — رنگ اصلی (مثال: ‎/brand_color #0F2A1D‎)
- ‎/brand_color2 <#HEX>‎ — رنگ ثانویه

- ‎/brand_position <center|top|bottom|top-left|top-right|bottom-left|bottom-right>‎
- ‎/brand_size <10..60>‎ — اندازه لوگو به درصد عرض
- ‎/brand_fidelity <0..100>‎ — وفاداری به طرح اصلی
- ‎/brand_redesign <0..100>‎ — شدت بازطراحی محدود
- ‎/watermark <متن>‎ و ‎/watermark_opacity <0..100>‎ — واترمارک سفارشی
- ‎/brand_save [نام]‎ و ‎/brand_load <نام>‎ — ذخیره و بازیابی پروفایل برند
- ‎/mode preserve|clean|redesign|branding‎ — چهار حالت پردازش
- ‎/clean <top|bottom|center|...>‎ — ناحیه پاک‌سازی
- ‎/tgs_layers‎ و ‎/tgs_hide <نام لایه>‎ — لایه‌های لوگو/متن TGS
- ‎/preview‎ — پیش‌نمایش واقعی: فایل اصلی و نهایی هر نمونه جداگانه فرستاده می‌شود
- ‎/process‎ — پردازش کامل فقط پس از تأیید پیش‌نمایش، با گزارش پیشرفت
- ‎/export‎ — ارسال ZIP + گزارش
- ‎/publish_new‎ — انتشار واقعی پک جدید با API رسمی (upload → createNewStickerSet → addStickerToSet)
- ‎/retry‎ — تلاش مجدد دانلودهای ناموفق
- ‎/cancel‎ — لغو پروژه و کار در صف
- ‎/status‎ — وضعیت پروژه و کارها

جریان عادی: ایموجی بفرستید (یا استیکر، یا لینک ‎t.me/addemoji/...‎، یا
فایل‌ها را مستقیم بفرستید) → مالکیت پک کامل را تأیید کنید → پروفایل برند
را تنظیم کنید → ناحیه پاک‌سازی را انتخاب کنید → ‎/preview‎ → تأیید →
‎/process‎ → ‎/export‎ یا ‎/publish_new‎.

## پاک‌سازی — صادقانه

- حالت A (استاندارد): ناحیه انتخاب‌شده با میانگین رنگ حلقه پیکسل‌های
  بلافاصله بیرون ناحیه پر می‌شود. برای نوارهای تخت لوگو/متن خوب است؛
  برای بافت پیچیده، پیش‌نمایش را ببینید و ناحیه را کوچک‌تر کنید. این Inpainting هوش مصنوعی نیست.
- حالت B (بازطراحی محدود): پاک‌سازی + تغییر ملایم رنگ/اشباع خارج از ناحیه،
  با حفظ پیکسل‌های شبه‌پوست (قاعده رنگی، نه تشخیص چهره). چهره به‌صورت خودکار
  شناسایی نمی‌شود؛ پیش‌نمایش، ضامن نهایی است.
- برای TGS: لایه‌هایی که نامشان شامل logo/text/name است، با ‎/tgs_layers‎
  دیده و با ‎/tgs_hide‎ پنهان می‌شوند و زمان‌بندی (fr/ip/op) دست نمی‌خورد.
- برای WEBM: فریم‌به‌فریم با همان پارامترها پردازش می‌شود تا رنگ نپرد و
  لوگو نلرزد؛ سپس با VP9 بدون صدا بازکدگذاری می‌شود.

## انتشار واقعی پک جدید (از نسخه ۰٫۲)

`/publish_new` دیگر فقط راهنما نمی‌دهد: در صف، برای هر فایل نهایی
`uploadStickerFile` صدا می‌شود، بعد `createNewStickerSet` با ۵۰ تای اول
(نوع `custom_emoji`) و بقیه با `addStickerToSet` اضافه می‌شوند و لینک
`https://t.me/addemoji/<name>_by_<bot>` فرستاده می‌شود. اگر فرمت‌ها
مخلوط باشند، انتشار متوقف و علت گفته می‌شود (یک ست فقط یک فرمت دارد).
اگر تلگرام خطا بدهد، همان خطا (بدون توکن) نشان داده می‌شود و مسیر دستی
ZIP پیشنهاد می‌شود — هیچ انتشار شبیه‌سازی‌شده‌ای وجود ندارد.

## نکته حقوقی

فقط پک‌هایی را پردازش کنید که مالک آن‌ها هستید یا اجازه تغییر و استفاده
تجاری‌شان را دارید. ربات پیش از دانلود پک کامل، همین تأیید را با دکمه
می‌گیرد و آن را برای کاربر ذخیره می‌کند. ربات مالکیت را به‌صورت خودکار
بررسی نمی‌کند؛ این مسئولیت کاربر است.

## مسیر تجاری (بدون پرداخت در نسخه اول)

ساختار پروژه/سفارش/مشتری از ابتدا جداست (‎storage‎ + ‎queue‎ + گزارش).
برای فروش آینده کافی است: ثبت سفارش + قیمت‌گذاری + درگاه پرداخت اضافه
شود؛ درگاه پرداخت بدون دستور صریح شما فعال نمی‌شود. فقط فایل‌هایی را
پردازش کنید که حق تغییرشان را دارید.


## نسخه ۹ — انتشار عمومی (دسترسی با تأیید مالک + برند ربات + شخصی‌سازی عمومی)

### الف) کنترل دسترسی و سهمیه (ماژول access.py)

- هر کاربر جدید با `/start` یا اولین پیام، با وضعیت **در انتظار تأیید (pending)** ثبت می‌شود؛ تا وقتی مالک تأیید نکند، هیچ قابلیتی (آپلود، پیش‌نمایش، پردازش، انتشار، منوها) برای او کار نمی‌کند و فقط پیام کوتاه وضعیت را می‌بیند.
- مالک (شناسه‌ی EMOJI_FORGE_OWNER_ID یا اولین شناسه‌ی EMOJI_FORGE_ADMIN_IDS) همان لحظه در چت خودش پیام «کاربر جدید» با دکمه‌های ✅ تأیید / ❌ رد می‌گیرد. این دکمه‌ها فقط برای مالک کار می‌کنند؛ هر کس دیگری آن‌ها را بزند فقط پاسخ رد می‌بیند و هیچ تغییری رخ نمی‌دهد.
- وضعیت‌ها: pending / approved / rejected / blocked. مالک همیشه تأییدشده و نامحدود است.
- مدیریت کاربران: دکمه «👥 کاربران» در منوی مالک + دستورهای `/users`، `/approve <id>`، `/reject <id>`، `/block <id>`، `/unblock <id>`، `/quota <id> <پک کل> <ایموجی کل> <پک روزانه>` و `/admin`. برای هر کاربر دکمه‌های آماده سهمیه هم هست (پیش‌فرض، پلاس، پرو، نامحدود) و سهمیه دلخواه عددی.
- **سهمیه پیش‌فرض کاربر تازه‌تأییدشده: ۳ پک در کل، ۱۰۰ ایموجی در کل، ۱ پک در روز** (ثابت‌های بالای فایل `access.py`).
- سهمیه **قبل از** صف‌کردن هر کار پردازش/انتشار بررسی می‌شود؛ شمارنده مصرف فقط وقتی کار **موفق تمام شود** زیاد می‌شود (کار ناموفق یا لغوشده سهمیه نمی‌خورد). شمارنده روزانه بر اساس تاریخ تهران است. پیام رد سهمیه، مصرف/سقف را نشان می‌دهد و می‌گوید با مالک در تماس باشید.
- پروفایل و دسترسی در همان فایل قبلی کاربر (`data/users/<id>.json`) نگه داشته می‌شود؛ نوشتن‌ها اتمیک‌اند (tmp + rename) و رجیستری کش حافظه‌ای دارد (اسکن پوشه فقط یک بار در هر اجرا).

### ب) برند خود ربات (ماژول branding.py)

- برند ربات: **Abolfazl** — اعتبار مالک: **Abolfazl • @Abolfazl_rwm**. در متن خوش‌آمد `/start`، راهنما/درباره («ساخته‌شده توسط Abolfazl — @Abolfazl_rwm»)، کپشن ZIP و گزارش («ساخته‌شده با Abolfazl») و پیام پایان انتشار دیده می‌شود.
- عنوان ست منتشرشده: اگر کاربر/طرح عنوان خودش را داده باشد، همان عنوان **بدون هیچ پسوندی** می‌ماند؛ فقط عنوان پیش‌فرض ساخته ربات پسوند « • Abolfazl» می‌گیرد.
- دستور مالک `/apply_branding`: نام ربات («Abolfazl | ایموجی‌ساز»)، توضیح کوتاه، توضیح کامل و فهرست دستورها را با متدهای رسمی تلگرام تنظیم می‌کند. فقط با دستور مالک اجرا می‌شود؛ خودکار نیست.
- خروجی کاربران همیشه با برند **خود کاربر** است و برند ربات آن را بازنویسی نمی‌کند. تنها استثنا: کلید «اعتبار ربات در خروجی کاربران» در بخش مدیریت — **پیش‌فرض خاموش**. وقتی روشن باشد، فقط برای کاربری که واترمارک خودش را تنظیم نکرده، واترمارک «Abolfazl» با همان سازوکار استاندارد واترمارک اضافه می‌شود.

### ج) شخصی‌سازی عمومی برای هر پک (ماژول‌های audit.py و logo_vector.py + حالت v8)

- **ممیزی عمومی پک (audit):** برای هر پک TGS ناشناخته، لایه‌ها/گروه‌ها از روی شواهد طبقه‌بندی می‌شوند: اول‌ازهمه **هندسه مشترک در کل پک** (شکلی که در بیشتر فایل‌ها تکرار شود واترمارک/لوگوست — برای هر پکی، بدون اسم خاص)، بعد الگوهای **عمومی** نام (logo/brand/watermark/…) و رنگ تم. اسم‌های اختصاصی پک قبلی (CDC/SVN/TON/FREE) دیگر قانون حذف نیستند، فقط مثال‌اند.
- **قاعده ایمنی:** اگر اطمینان تشخیص لوگو پایین باشد، پردازش خودکار انجام نمی‌شود و پک به صف بررسی شخصی متی می‌رود — لایه نامطمئن هرگز بی‌سروصدا حذف نمی‌شود. گزارش ممیزی در فایل `audit.json` هر پروژه ذخیره می‌شود و فقط نام‌های با اطمینان بالا به فهرست حذف اضافه می‌شوند.
- **حالت v8 برای همه کاربران:** لوگوی تصویری کاربر به‌صورت خودکار به شکل برداری تبدیل (trace) می‌شود و با قاعده **فیت دقیق** — کامل داخل قاب لوگوی قبلی، با همان ترتیب لایه/پدر/انیمیشن — می‌نشیند. بدون لوگوی تصویری، مسیر متن دقیق v5/v6 اجرا می‌شود. حالت اندازه لوگو از تنظیمات پیشرفته قابل تغییر است: fit (پیش‌فرض) یا fill (رفتار قدیمی).
- هر سه فرمت در همان جریان پیش‌نمایش ← تأیید ← پردازش ← انتشار: TGS (موتور برداری)، WEBM و تصویر ثابت (موتور رستری؛ در حالت v8 آیتم‌های رستری با موتور strip پردازش می‌شوند).
- سطح شخصی‌سازی هر کاربر: نام برند، لوگوی تصویری، رنگ اصلی/دوم + طیف رنگی، **فونت متن رستری** (سه سبک: ضخیم بدون‌سریف / سریف / تک‌عرض، از تنظیمات پیشرفته)، محل و اندازه لوگو، واترمارک، و حالت‌های preserve/clean/redesign/branding/strip/v8.

### د) بهینه‌سازی و استحکام

- دروازه اعتبارسنجی قبل از آپلود روی **هر دو** مسیر انتشار است: انتشار کامل (validate_final_dir) و انتشار تکی یک فایل (`publish_single_file` — مسیر تعمیر وقتی انتشار کامل روی یک فایل می‌ایستد)؛ فاصله ۳ ثانیه‌ای آپلودها و احترام به retry_after تلگرام در هر دو مسیر.
- ری‌استارت ربات: کارهای مانده در وضعیت «در حال اجرا» خودکار «نیمه‌تمام (interrupted)» با دلیل فارسی علامت می‌خورند، نه اینکه برای همیشه آویزان بمانند.
- خودآزمایی شروع (بدون شبکه): پوشه‌های داده، فایل شکل‌های لوگو و فونت‌ها بررسی و یک خط آمادگی `[forge]` چاپ می‌شود.

## نسخه ۱۰ — آپدیت بزرگ (گارد ایمپورتر + انتشار قابل ادامه + UX + رجیستری)

### الف) گارد ایمپورتر (ماژول importer_guard.py + اعتبارسنج جدید)

سه درس سخت از دورهای اصلاح پک ۲۰۰ فایلی (تست زنده ۲۰۲۶-۱۰-۳۰) حالا قانون کد است:

- **گروه بدون tr پایانی = خطای مسدودکننده.** ایمپورتر تلگرام هر فایلی را که گروهی بدون آیتم `tr` در انتها داشته باشد رد می‌کند، هرچند rlottie آن را درست رندر می‌کند.
- **امضای رنگ‌آمیزی گروهی = خطای مسدودکننده.** گروهی بدون شکل مستقیم، با حداقل دو زیرگروه و هر دو رنگ گروهی `fl` و `st` (امضای دقیق `[gr, gr, gr, fl, st, tr]` گروه‌های برند متن‌محور) رد می‌شود. نکته کالیبراسیون صادقانه: خوانش تحت‌اللفظی «fl یا st» روی ۴۲۰ فایل پذیرفته‌شده تلگرام ۱۶۶ مثبت کاذب می‌داد (گروه‌های تک‌رنگِ صحنه سالم‌اند)؛ امضای پیاده‌شده روی هر ۴ فایل بدِ اثبات‌شده صدق می‌کند و روی فایل‌های سالم صفر است.
- **گروه با بیش از ۹۰۰ رأس = هشدار** (سقف ایمپورتر به بافت فایل بستگی دارد؛ فایل ۰۹۷). `fix_importer_risks()` به‌صورت خودکار tr هویتی اضافه می‌کند، رنگ‌های گروهیِ امضای ردشونده را حذف می‌کند (زیرگروه‌ها رنگ خودشان را دارند) و فقط در گروه‌های بالای ۱۱۰۰ رأس، مسیرهای با مماس صفر را با Douglas-Peucker ساده می‌کند؛ مسیرهای منحنی‌دار دست نمی‌خورند و در گزارش «ردشده» ثبت می‌شوند. تابع idempotent است و ورودی را تغییر نمی‌دهد.
- گارد روی **هر دو مسیر تحویل** سوار است: خروجی هر TGS در `process_project` و در `process_single` (و یک بار دیگر در دروازه تحویل بات) از گارد + اعتبارسنجی می‌گذرد؛ فایلی که بعد از گارد هم مسدود باشد، با صدای بلند fail می‌شود و تحویل داده نمی‌شود.

### ب) انتشار مقاوم و قابل ادامه

- `_call` تلگرام حالا یک پوشش مقاوم مرکزی است: حداکثر ۴ تلاش با backoff نمایی ۲/۴/۸ ثانیه؛ تلاش مجدد روی خطای شبکه، روی 429 با احترام به `retry_after` تلگرام (خواب = بیشینه backoff و retry_after) و روی دو خطای 400 گذرای اثبات‌شده («file must be non-empty» و «wrong file type»). بقیه خطاها (401/409/400 واقعی) فوراً surface می‌شوند. هندل فایل‌های آپلودی پیش از هر تلاش مجدد rewind می‌شود.
- هر پروژه یک `publish_progress.json` دارد: file_id هر استیکر آپلودشده و وضعیت انتشارش ثبت می‌شود؛ اجرای دوباره جاب انتشار، استیکرهای تمام‌شده را رد می‌کند (آپلود تکراری و ست دوم ساخته نمی‌شود) و اگر ست ساخته شده باشد فقط استیکرهای باقی‌مانده را اضافه می‌کند. ایموجی هر استیکر از `manifest.json` خود پروژه خوانده می‌شود، نه مقدار ثابت.

### ج) تجربه کاربری

- نسخه بسته **10.0.0**؛ `/start` و `/help` «نسخه ۱۰» و فهرست «تازه‌های نسخه ۱۰» را نشان می‌دهند.
- پردازش و انتشار، **یک** پیام وضعیت را ویرایش می‌کنند: نوار پیشرفت بلوکی با درصد و اعداد فارسی و زمان تقریبی باقی‌مانده (ماژول `progress.py`)، با throttle حداکثر یک ویرایش در ~۳ ثانیه یا هر گام ۵٪. اگر پیام قابل ویرایش نباشد، گزارش‌های milestone قدیمی جایگزین می‌شوند.
- دکمه «📦 پک‌های من» (`/mypacks`): پروژه‌ها و ست‌های منتشرشده کاربر با لینک؛ دکمه و دستور مالک «📊 آمار ربات» (`/stats`): کاربران به تفکیک وضعیت، تعداد پروژه‌ها، استیکرهای پردازش‌شده و وضعیت صف.
- پیش‌نمایش: یک **شیت تماس قبل/بعد** (رندر rlottie برای TGS، تصویر مستقیم برای رستری) به‌صورت عکس فرستاده می‌شود؛ اگر رندر ممکن نباشد، بی‌سروصدا به رفتار قبلی برمی‌گردد.

### د) رجیستری بزرگ‌تر

- رنگ‌ها از ۸۴ به **۱۱۲** رسید (چهار خانواده جدید: نئون فوق‌درخشان، پاستل ملایم، متالیک براق، خاکی) — همه hexها یکتا.
- **۱۴ گرادیان آماده** دو رنگ (id پایدار + نام فارسی + color1/color2) با API `gradients()`/`gradient_by_id()`؛ انتخاب گرادیان در انتخاب‌گر رنگ ایموجی تکی و در تنظیمات برند پک، primary و secondary را ست و طیف را فعال می‌کند. `assets/registry.json` بازتولید شده و گرادیان‌ها را هم دارد.

### وضعیت تست نسخه ۱۰ (صادقانه)

- همه موارد بالا با تست واحد/موک پوشیده شده‌اند (`tests/test_v10.py`: گارد، هر دو امضای ولیدیتور، retry گذرا/دائم/429/شبکه، ادامه انتشار از چک‌پوینت، گرادیان، نوار پیشرفت) و گارد/ولیدیتور روی ۴۲۰ فایل واقعی پذیرفته‌شده تلگرام کالیبره شده‌اند (صفر مثبت کاذب؛ هر ۴ فایل بدِ بایگانی‌شده شناسایی و تعمیر شدند).
- **زنده تأیید نشده:** بات در این نوبت توکن نداشت؛ هیچ فراخوانی زنده به تلگرام انجام نشد. ویرایش پیام وضعیت، ارسال عکس شیت تماس و ادامه انتشار، در دیپلوی بعدی با توکن باید یک بار زنده چک شوند.

### محدودیت‌های صادقانه نسخه ۹

- برداری‌سازی لوگوی کاربر **سیلوئت** است: در خروجی TGS لوگو سفید با دورخط تیره رندر می‌شود (ابزار خوانایی خانه) و رنگ‌های داخلی یک لوگوی چندرنگ در TGS حفظ نمی‌شود؛ در خروجی‌های رستری (WEBM/ثابت) تصویر اصلی لوگو استفاده می‌شود.
- ممیزی عمومی بر پایه هندسه مشترک و نام‌های عمومی است؛ پکی که لوگويش در هر فایل متفاوت باشد یا وسط بافت پیچیده مخفی شده باشد، اطمینان پایین می‌گیرد و به بررسی شخصی می‌رود — عمداً حدس زده نمی‌شود.
- جریان تأیید کاربر و `/apply_branding` با تست‌های موک پوشش داده شده‌اند اما تا دیپلوی و تست با یک حساب دوم، **زنده تأیید نشده‌اند** (مراحل در DEPLOY-FA.md).
